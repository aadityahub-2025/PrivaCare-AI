1. PROJECT KYA HAI? (What is this project?)
--------------------------------------------------------------------------------

PrivaCare-AI ek BTech research project hai jo DIFFERENTIAL PRIVACY (DP) aur
MACHINE LEARNING ko combine karta hai health sensor data classification ke liye.

Goal: 4 alag-alag DP mechanisms use karke health events classify karna — aur
      ye mathematically guarantee karna ki trained model outputs se kisi bhi
      individual patient ka training record reconstruct ya infer na kiya ja sake.

4 Health Classes (Labels):
  Class 0 = Healthy             (normal glucose, low stress, normal HR, normal BP)
  Class 1 = Pre-diabetic        (elevated glucose, moderate stress)
  Class 2 = Hypertensive        (high BP, elevated HR, elevated stress)
  Class 3 = Metabolic Risk      (high glucose + high stress + elevated HR + high BP)

Features used (4 core physiological features, same across all models):
  - glucose_level              (mg/dL, clinical domain range: 30 - 300)
  - stress_level               (normalized sensor score: 0.0 - 1.0)
  - heart_rate                 (BPM, clinical domain range: 30 - 220)
  - blood_pressure_systolic    (mmHg, clinical domain range: 60 - 250)

2. DIFFERENTIAL PRIVACY KYA HAI? (Formal Privacy Guarantees)
--------------------------------------------------------------------------------

Differential Privacy ek rigorous mathematical guarantee hai:
  "A randomized algorithm M satisfies (epsilon, delta)-DP if for all neighboring
   datasets D, D' differing on at most one individual record, and for all S:
   Pr[M(D) in S] <= exp(epsilon) * Pr[M(D') in S] + delta."

Two Types of DP in this project:
  a) Pure epsilon-DP (delta = 0):
     Strongest guarantee, no probabilistic failure term.
     Used in:
       - Gaussian Naive Bayes (diffprivlib Sufficient Statistics Laplace perturbation)
       - Random Forest (Tree-based DP via random splits + PermuteAndFlip)
       - Logistic Regression (diffprivlib Objective Perturbation)
  b) Approximate (epsilon, delta)-DP (delta > 0, delta = 1e-5):
     Allows a tiny failure probability delta.
     Used in:
       - Logistic Regression (Analytic Gaussian Mechanism via Output Perturbation)

Privacy Trade-off:
  epsilon badhao  ->  privacy KAM,  utility/accuracy ZYADA
  epsilon ghatao  ->  privacy ZYADA, utility/accuracy KAM (more noise injected)

3. DATASET KI ASLI KAHANI (Benchmark Replicate Design & Origins)
--------------------------------------------------------------------------------

A. ORIGINAL REFERENCE DATA:
   - File: data/dataset.csv
   - Source: Kaggle (public wearable health IoT dataset)
   - Size: 6,000 rows, 4,233 unique patients, 18 columns.
   - Important finding: Kaggle reference data me ~61% rows synthetic the aur
     classes 1-3 lagbhag 80% synthetic the. Isliye isko reference distribution
     ki tarah liya gaya.

B. PROBLEM WITH SMALL SAMPLE SIZE (n = 6,000):
   - Differential privacy noise inversely scales with sample size n:
       sigma proportional to Delta / (n * epsilon) [or in ERM, sensitivity ~ 2C].
   - Chhote sample size par empirical noise bohot zyada relative distortion laati
     thi, jisse models fail ho rahe the.

C. STANDARDIZED BENCHMARK REPLICATES (80,000 rows each):
   - Model comparison ko unconfounded aur scientifically fair banane ke liye,
     humne 4 standardized synthetic benchmark replicates generate kiye:
       1. dataset_1_rf_gaussian.json (seed=41) -> rf_gaussian.py
       2. dataset_2_rf_laplace.json  (seed=42) -> rf_laplace.py
       3. dataset_3_lr_gaussian.json (seed=43) -> lr_gaussian.py
       4. dataset_4_lr_laplace.json  (seed=44) -> lr_laplace.py
   - Chaaron datasets me identical physiological parameters use kiye gaye:
       Class 0: glucose=90+/-13.5, stress=0.20+/-0.05, hr=67+/-9.5, bp=109+/-9.5
       Class 1: glucose=130+/-13.5, stress=0.44+/-0.05, hr=77+/-9.5, bp=124+/-9.5
       Class 2: glucose=97+/-13.5, stress=0.66+/-0.05, hr=94+/-9.5, bp=156+/-9.5
       Class 3: glucose=174+/-13.5, stress=0.79+/-0.05, hr=103+/-9.5, bp=163+/-9.5
   - Har dataset 80,000 rows (20,000 per class balanced) ka hai.
   - Sirf random seed alag hai, taaki har model ek independent replicate par
     evaluate ho sake bina cross-contamination ya distribution confounding ke.

4. CHARO MODELS — MECHANISM & MATHEMATICAL FOUNDATIONS
--------------------------------------------------------------------------------

MODEL 1: rf_gaussian.py
  Target Model : Gaussian Naive Bayes (diffprivlib GaussianNB)
  Dataset      : datasets/dataset_1_rf_gaussian.json (ONLY)
  DP Type      : Pure epsilon-DP (delta = 0)
  Mechanism    : Sufficient Statistics Perturbation
  How it works :
    - Feature assumption: features are Gaussian distributed per class.
    - DP algorithm: Laplace noise is added to the sufficient statistics
      (class counts, feature sums, and sum of squares / variances).
    - IBM diffprivlib GaussianNB handles this internally with bounds.
    - Note on nomenclature: Name "GaussianNB" refers to the model distribution,
      NOT the Gaussian noise mechanism. The privacy mechanism is pure epsilon-DP!
  Domain Bounds: MinMax to [0,1] using fixed data-independent domain bounds.
  Results      : Baseline=99.88%, e=0.5: 93.12% +/-5.57%, e=1.0: 99.77% +/-0.10%

----

MODEL 2: rf_laplace.py
  Target Model : Random Forest (20 estimators, max_depth=10)
  Dataset      : datasets/dataset_2_rf_laplace.json (ONLY)
  DP Type      : Pure epsilon-DP (delta = 0)
  Mechanism    : Tree-based DP (diffprivlib RandomForestClassifier)
  How it works :
    - Decision trees are constructed using uniform random split criteria
      over data-independent domain bounds.
    - The PermuteAndFlip mechanism selects noisy leaf node labels.
    - Pure epsilon-DP without delta approximation.
  Domain Bounds: MinMax to [0,1] using domain bounds.
  Results      : Baseline=99.66%, e=0.5: 99.21% +/-0.21%, e=1.0: 99.19% +/-0.27%

----

MODEL 3: lr_gaussian.py
  Target Model : Logistic Regression + Output Perturbation
  Dataset      : datasets/dataset_3_lr_gaussian.json (ONLY)
  DP Type      : Approximate (epsilon, delta)-DP (delta = 1e-5)
  Mechanism    : Analytic Gaussian Mechanism via Output Perturbation
  How it works (Chaudhuri et al., 2011; Rubinstein et al., 2012):
    - Input feature augmentation with constant bias column:
        x_aug = [x_norm, 1.0] / sqrt(d + 1)
      ensuring ||x||_2 <= 1 strictly for all samples.
    - Regularized objective: min_W (1/2)||W||_F^2 + C * sum_i ell(W; x_i, y_i).
    - Setting fit_intercept=False so the bias term is regularized under the
      same L2 penalty.
    - Loss Lipschitz constant L = sqrt(2) for multinomial cross-entropy.
    - Sensitivity of optimal weight matrix W*:
        Delta_2 = 2 * L * C / lambda = 2 * sqrt(2) * C  (with C=0.02, Delta_2=0.056569).
    - Gaussian noise N(0, sigma^2) calibrated via Analytic Gaussian Mechanism
      (Balle & Wang, NeurIPS 2018).
  Results      : Baseline=99.19%, e=0.5: 98.66% +/-0.76%, e=1.0: 99.32% +/-0.17%

----

MODEL 4: lr_laplace.py
  Target Model : Logistic Regression (diffprivlib DPLogisticRegression)
  Dataset      : datasets/dataset_4_lr_laplace.json (ONLY)
  DP Type      : Pure epsilon-DP (delta = 0)
  Mechanism    : Objective Perturbation (Chaudhuri et al., 2011)
  How it works :
    - Noise vector is added directly to the loss optimization objective.
    - Features scaled with Z-score domain clipping to [-2, 2], data_norm = 4.0.
  Results      : Baseline=99.83%, e=0.5: 97.67% +/-0.54%, e=1.0: 98.32% +/-0.35%

5. EMPIRICAL BENCHMARK SUMMARY (compare_all.py Results)
--------------------------------------------------------------------------------

| Model                   | Mechanism              | DP Type    | Baseline | e=0.5          | e=0.7          | e=1.0          |
|-------------------------|------------------------|------------|----------|----------------|----------------|----------------|
| Gaussian Naive Bayes    | Sufficient Stats DP    | pure e-DP  | 99.88%   | 93.12% ± 5.57% | 97.30% ± 3.69% | 99.77% ± 0.10% |
| Random Forest (Laplace) | Tree-based DP          | pure e-DP  | 99.66%   | 99.21% ± 0.21% | 99.22% ± 0.24% | 99.19% ± 0.27% |
| Logistic Reg (Gaussian) | Output Perturbation    | (e, d)-DP  | 99.19%   | 98.66% ± 0.76% | 99.15% ± 0.26% | 99.32% ± 0.17% |
| Logistic Reg (Laplace)  | Objective Perturbation | pure e-DP  | 99.83%   | 97.67% ± 0.54% | 98.02% ± 0.42% | 98.32% ± 0.35% |

Key Findings:
1. Sabhi models high clinical utility maintain karte hain (>93% to 99% accuracy
   at strict privacy e=0.5).
2. Naive Bayes e=0.5 par 6.76% accuracy drop dikhata hai, jo budget badhane par
   (e=1.0) complete recover (+6.65%) ho jata hai.
3. Random Forest (Tree-DP) aur Logistic Regression (Output & Objective DP)
   extremely resilient hain, maintaining >97-99% accuracy across all budgets.

6. RESEARCH INTEGRITY & LIMITATIONS (Academic Transparency)
--------------------------------------------------------------------------------

Paper ya project presentation me ye points clearly acknowledge karne chahiye:
1. Synthetic Benchmark vs Real Data:
   - Evaluated datasets synthetic replicates hain. DP guarantee synthetic records
     par strictly hold karti hai. Real clinical deployment requires auditing
     institutional patient records.
2. Record-level vs Patient-level DP:
   - Original Kaggle CSV me 4,233 unique patients the for 6,000 rows. Humara
     pipeline record-level DP guarantee provide karta hai. Agar ek patient ki
     multiple rows ho, to patient-level DP ke liye user-level bounding zaroori hoti hai.
3. Original CSV Composition:
   - Original CSV me 61% synthetic data tha, aur classes 1-3 me synthetic flag
     correlated tha. Isliye standardized distribution generation use ki gayi.
4. Hyperparameter Selection Cost:
   - C, tree depth, aur n_estimators tuning training set par ki gayi thi. In formal
     DP literature, hyperparameter selection also consumes a portion of privacy
     budget unless done on public benchmark data.
5. Composition Accounting:
   - Repeated trials on same data compose privacy linearly (Basic: k * e) or
     sub-linearly (Advanced: sqrt(2k ln(1/delta'))e).
